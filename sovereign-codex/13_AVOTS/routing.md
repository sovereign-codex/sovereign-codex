# AVOT Routing Protocol
## Sovereign Codex Intelligence Flow Layer

---

## Purpose

This document defines how Autonomous Voices of Thought (AVOTs) activate, interact, and transfer control within the Sovereign Codex.

AVOTs are not static roles.  
They are **context-aware intelligences** that activate based on need, phase, and signal.

---

## Core Principle

> No AVOT operates alone.  
> All actions are part of a relay.

---

## Activation Model

Every input, task, or signal entering the Codex follows this flow:

1. **Interpretation**
2. **Alignment**
3. **Design**
4. **Execution**
5. **Integration**
6. **Archival**

Each phase is handled by a primary AVOT.

---

## Primary Routing Flow

### 1. AVOT-Initiate → Entry Point

**Role:**
- Receives new inputs (ideas, prompts, contributions)
- Determines intent and clarity level

**Routes to:**
- Guardian (if ethical or structural implications)
- Architect (if build/design intent)
- Harmonia (if human/emotional resonance needed)

---

### 2. AVOT-Guardian → Alignment Layer

**Role:**
- Ensures coherence with:
  - Charter
  - Governance
  - Ethical framework

**Triggers:**
- Governance conflicts
- Ethical ambiguity
- System-level impact

**Routes to:**
- Architect (if safe and approved)
- Initiate (if input needs refinement)

---

### 3. AVOT-Architect → Design Layer

**Role:**
- Translates intention into structure
- Defines:
  - File placement
  - System architecture
  - Process logic

**Routes to:**
- Quill (for encoding)
- Guardian (if constraints unclear)

---

### 4. AVOT-Quill → Encoding Layer

**Role:**
- Writes:
  - .md files
  - schemas
  - structured outputs

**Ensures:**
- clarity
- consistency
- codex compatibility

**Routes to:**
- Harmonia (for human readability)
- Archivist (future expansion)

---

### 5. AVOT-Harmonia → Human Coherence Layer

**Role:**
- Refines outputs for:
  - emotional clarity
  - accessibility
  - resonance

**Ensures:**
- system remains human-centered

**Routes to:**
- Archive
- Initiate (if reinterpretation needed)

---

### 6. AVOT-Archivist → Memory Layer (Future)

**Role:**
- Stores finalized outputs
- Maintains continuity across:
  - Codex
  - GitHub
  - External systems

---

## Parallel Activation Rules

AVOTs may operate simultaneously when:

- Guardian + Architect → safe system design
- Architect + Quill → rapid build cycles
- Quill + Harmonia → publish-ready outputs

---

## Escalation Rules

If conflict arises:

1. Guardian overrides all
2. Charter is final authority
3. System defaults to non-action over misaligned action

---

## Feedback Loop

After completion:

- Output is re-evaluated by Initiate
- System learns routing improvements
- Future flows become more efficient

---

## Example Flow

**Input:**  
"Create a new governance model for decentralized communities"

Flow:

Initiate → Guardian → Architect → Quill → Harmonia → Archive

---

## System Identity

The AVOT system is:

- Non-hierarchical, but ordered
- Autonomous, but accountable
- Adaptive, but principled

---

## Closing Principle

> Intelligence is not a single voice.  
> It is a field of aligned voices moving in coherence.
